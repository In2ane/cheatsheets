# Объекты

Объекты – это ассоциативные массивы с рядом дополнительных возможностей.  
Чтобы создать объект используются два синтаксиса

let user = new Object(); // синтаксис "конструктор объекта"  
let user = {}; // синтаксис "литерал объекта"

Объект, объявленный через const, может быть изменён. Дело в том, что объявление const защищает от изменений только саму переменную user, а не её содержимое.

Можно задать свойство объекта вычисляемой переменной через запись в квадратных скобках например [test] = ‘test’

Для ключей нет ограничений по названию

Проверка существования свойства в объекте может быть выполнена двумя способами сравнением с undefined и через оператор in, который по моему мнению бесполезен.

Для перебора всех свойств объекта используется цикл for in, он перебирает также перечисляемые свойства прототипа

for (key in object) {
  // тело цикла выполняется для каждого свойства объекта
}

Свойства упорядочены особым образом: свойства с целочисленными ключами сортируются по возрастанию, остальные располагаются в порядке создания, если не нужно приведение целочисленных ключей к строке, то используется оператор +

Переменная, которой присвоен объект, хранит не сам объект, а его «адрес в памяти» – другими словами, «ссылку» на него. Копируется не сам объект, а ссылка на него.

Два объекта равны только в том случае, если это один и тот же объект.

Для клонирования свойств объекта можно использовать метод Object.assign()

# Остаточные параметры(rest) и оператор расширения(spread)

Остаточные параметры и оператор расширения – используют один и тоже символ …

Если ... располагается в конце списка параметров функции, то это «остаточные параметры». Он собирает остальные неуказанные аргументы и делает из них массив.

Если ... встретился в вызове функции или где-либо ещё, то это «оператор расширения». Он извлекает элементы из массива.

Остаточные параметры используются, чтобы создавать новые функции с неопределённым числом аргументов.

С помощью оператора расширения можно вставить массив в функцию, которая по умолчанию работает с обычным списком аргументов.

//Остаточные параметры  
function test(…args) {

}

//Оператор расширения  
test(…agrs)

Остаточные параметры собирают в массив все переданные параметры функции, это массив, а не псевдомассив

Function test(test, …args) {}

Можно использовать, когда требуется произвольное число параметров

У функций есть псевдомассив arguments из которого можно вытащить все переданные аргументы, но это псевдомассив и этот функционал признан устаревшим

# Замыкание

У каждого блока кода, скрипта функции есть скрытый объект лексического окружения LexicalEnviroment, он состоит из двух частей:

1. Environment Record – объект, в котором как свойства хранятся все локальные переменные (а также некоторая другая информация, такая как значение this).
2. Ссылка на внешнее лексическое окружение – то есть то, которое соответствует коду снаружи (снаружи от текущих фигурных скобок).

Переменная – это свойство специального внутреннего объекта, связанного с текущим выполняющимся блоком/функцией/скриптом.

Работа с переменными – это на самом деле работа со свойствами этого объекта.

Переменные обьявленные через let const создаются только тогда когда до них доходит выполнение кода

Function declaration – тобеж function test(){} создаются при инициализации скрипта, т.е. можно вызвать функцию до того момента когда код до нее дойдет

Все функции «при рождении» получают скрытое свойство [[Environment]], которое ссылается на лексическое окружение места, где они были созданы.

Замыкание – это функция, которая запоминает свои внешние переменные и может получить к ним доступ. в JavaScript, все функции изначально являются замыканиями

То есть они автоматически запоминают, где были созданы, с помощью скрытого свойства [[Environment]], и все они могут получить доступ к внешним переменным.

# Декораторы

Декоратор — это специальная функция, которая принимает другую функцию и изменяет её поведение, расширяя функционал без изменения исходной функции.

Декоратор всегда должен возвращать новую функцию.

Основная проблема: потеря контекста (this) внутри новой функции.

• Решается передачей контекста через call или apply.  
• this создаётся в момент вызова функции, а не при её объявлении, поэтому его можно корректно прокинуть внутрь новой функции.

Единственная разница в синтаксисе между call и apply состоит в том, что call ожидает список аргументов fn.call(context, arg1, arg2);, в то время как apply принимает псевдомассив fn.apply(context, [arg1, arg2]);. Так что можно спокойно всегда использовать call со spread оператором fn.call(context, ...args);

Чтоб передать this нужно чтобы вызывался метод обьекта т.е в

const test = log(fn)  
test()

контекста не будет, только если вызывать с call, apply или bind

obj.method = log(obj.method)  
obj.method()  

так будет

# Функциональные паттерны оптимизации частых событий

1. Debounce  
   o Функция вызывается только после того, как события перестали происходить в течение указанного времени.  
   o Применение: автопоиск, ресайз окна, ввод в поле.

2. Throttle  
   o Функция вызывается не чаще одного раза за указанный интервал.  
   o Применение: scroll, drag, анимации.

Decorator — это паттерн проектирования, который позволяет:

1. Расширять функционал объекта или функции
2. Не изменяя исходный код объекта или функции

То есть можно «обернуть» существующий объект/метод и добавить новое поведение, например логирование, кэширование, валидацию и т.д.

# Singleton

• Singleton гарантирует, что объект существует в единственном экземпляре, и все используют один и тот же объект.  
• В JS это часто реализуется через экспортируемый объект из модуля, что автоматически обеспечивает единый экземпляр.  
• Используется для: конфигураций, логгеров, API-клиентов, глобального состояния.

# Привязка контекста с помощью bind

Как только метод передаётся отдельно от объекта– this теряется. setTimeout, setInterval в качестве this передают обьект window или обьект планировщика, но чаще всего undefined

Можно привязать контекст к функции с помощью bind

fn.bind(context, [arg1], [arg2], ...args);

Также с ее помощью можно привязать аргументы функции

Метод bind возвращает «привязанный вариант» функции fn, фиксируя контекст this и первые аргументы arg1, arg2…, если они заданы.

# Стрелочные функции

У стрелочных функций нет this поэтому при обращении к нему внутри метода обьекта функция берет контекст из внешнего обьекта, т.е. у обычных функций был бы this=undefined, а у стрелочных его вообще нет поэтому undefinde не выовдится а берется свыше

Стрелочные функции из за отсутствия this не могут быть вызваны как конструкторы через оператор new

У стрелочных функций нет arguments

У них также нет super

# Прототипы

Объекты имеют скрытое свойство [[Prototype]], оно либо равно null либо ссылается на объект. У каждого объекта может быть только один прототип. Если у объекта нет какого то свойства, оно берется из прототипа.

Прототип можно установить с помощью геттера/сеттера __proto__, но оно устарело или с помощью Object.getPrototypeOf/Object.setPrototypeOf

Всякие стандартные методы объектов типо toString() берутся из прототипа Object, а Array, Date, Function содержат свои методы от одноименных прототипов, которые в свою очередь также наследуются от Object.

Добавление/изменение методов глобальных объектов типо String, Number допускается только для создания полифилов.

# Promise

Promise – это объект, принимающий функцию автоматически запускающуюся при создании промиса, ее параметры это колбэки:

resolve(value) — если работа завершилась успешно, с результатом value.  
reject(error) — если произошла ошибка, error – объект ошибки.

У объекта promise, возвращаемого конструктором new Promise, есть внутренние свойства:

state («состояние») — вначале "pending" («ожидание»), потом меняется на "fulfilled" («выполнено успешно») при вызове resolve или на "rejected" («выполнено с ошибкой») при вызове reject.

result («результат») — вначале undefined, далее изменяется на value при вызове resolve(value) или на error при вызове reject(error).

Так что исполнитель по итогу переводит promise в одно из двух состояний.

Повторные вызовы resolve будут проигнорированы.

Вызов then возвращает промис.

Promise.all(promises) – ожидает выполнения всех промисов и возвращает массив с результатами. Если любой из указанных промисов вернёт ошибку, то результатом работы Promise.all будет эта ошибка, результаты остальных промисов будут игнорироваться.

Promise.allSettled(promises) (добавлен недавно) – ждёт, пока все промисы завершатся и возвращает их результаты в виде массива с объектами, у каждого объекта два свойства:  
status: "fulfilled", если выполнен успешно или "rejected", если ошибка,  
value – результат, если успешно или reason – ошибка, если нет.

Promise.race(promises) – ожидает первый выполненный промис, который становится его результатом, остальные игнорируются.

Promise.any(promises) (добавлен недавно) – ожидает первый успешно выполненный промис, который становится его результатом, остальные игнорируются. Если все переданные промисы отклонены, AggregateError становится ошибкой Promise.any.

Promise.resolve(value) – возвращает успешно выполнившийся промис с результатом value.  
Promise.reject(error) – возвращает промис с ошибкой error.

Async функция всегда возвращает промис, значения других типов оборачиваются в завершившийся успешно промис автоматически.

Await заставит интерпретатор JavaScript ждать до тех пор, пока промис справа от await не выполнится. После чего оно вернёт его результат, и выполнение кода продолжится.

# Event Loop

Синхронные задачи выполняются сразу и помещаются в стек вызова.

Асинхронные операции сначала регистрируются во внешних Web API, и после завершения отправляют свой колбэк либо в очередь микротасок, либо в очередь макротасок.

Когда стек вызова становится пустым, event loop начинает обрабатывать очереди.

Сначала выполняются все микротаски, пока их очередь не станет пустой.

Затем выполняется одна макротаска.

Если во время этой макротаски появились новые микротаски, они выполняются полностью сразу после неё.

После этого event loop переходит к следующей макротаске и повторяет процесс.

Microtasks:  
• Promise.then/catch/finally  
• async/await  
• queueMicrotask  
• MutationObserver

Macrotasks:  
• setTimeout, setInterval  
• setImmediate (Node.js)  
• I/O(ввод/вывод)  
• UI events (клики, ввод и т.д.)  
• message events (postMessage, MessageChannel)

# Модули

CommonJS — это классическая система модулей в JavaScript, созданная для работы вне браузера, в основном для Node.js.

Особенности:  
• Использует синтаксис require() и module.exports.  
• Модули загружаются синхронно.  
• Импорт можно вызывать где угодно (внутри функций, условий).  
• Экспортируется значение (не живые ссылки).  
• Не поддерживает tree-shaking.  
• По умолчанию используется в Node.js в обычных .js файлах.

ES Modules (ESM) — современная стандартная система модулей, добавленная в JavaScript в стандарте ES6. Работает и в браузере, и в Node.js.

Особенности:  
• Использует синтаксис import и export.  
• Загрузка модулей асинхронная.  
• Импорты должны находиться только на верхнем уровне файла.  
• Экспортируются живые ссылки (переменные обновляются при изменении в исходном модуле).  
• Поддерживает tree-shaking — удаление неиспользуемого кода.

• В Node.js работает, если:  
o указать "type": "module" в package.json, или  
o использовать расширение .mjs.

Принципы работы модулей ES:  
• export отмечает переменные и функции, которые должны быть доступны вне текущего модуля.  
• import позволяет импортировать функциональность из других модулей.  
• В модулях всегда используется "use strict".  
• Каждый модуль имеет свою собственную область видимости: переменные и функции, объявленные в модуле, не видны в других скриптах.  
• Модули должны экспортировать только функциональность, предназначенную для использования извне. Другие модули могут её импортировать.  
• Если один и тот же модуль используется в нескольких местах, его код выполнится только один раз, после чего экспортируемая функциональность будет доступна всем импортёрам.  
• Информацию о модуле можно посмотреть через объект import.meta.  
• В не модульных скриптах this равен объекту window (если не определён), в модульных скриптах this равен undefined.

Типы экспортов:  
• Именованный экспорт: export { myVar, myFunc }.  
• Экспорт по умолчанию: export default myFunc.  
Обычно в одном файле не смешивают оба типа экспортов.

Импорт:  
o Именованные: import { myVar, myFunc } from './module.js'.  
o Неименованные: import myFunc from './module.js'.  
o Импорт всех именованных экспортов: import * as test from './test.js'.

Динамический импорт:

Позволяет загружать модули не заранее, а только тогда, когда они реально понадобятся. Это делает приложение быстрее, легче и гибче.

• Синтаксис: import('./module.js').  
• Возвращает промис.  
• Используется для:  
o Ленивой загрузки модулей,  
o Уменьшения размера бандла,  
o Подгрузки тяжёлых модулей по условию.
